# Familiar demo: parcel bay ledger

This is an original, deliberately reusable practice demonstration, **not a
score-eligible unseen interview**. Its provenance is `origin.kind: "demo"`.
Neither the scenario nor its extensions are copied from a real interview.
Exposure to this pack, this directory, or either reference makes subsequent
attempts familiar. Demo attempts must not improve unseen-interview trends.

From the project root:

```console
python -m interview_lab demo --id ledger-walkthrough --language python
python -m interview_lab start ledger-walkthrough --familiar yes
python -m interview_lab show ledger-walkthrough
python -m interview_lab test ledger-walkthrough --public
python -m interview_lab done ledger-walkthrough
python -m interview_lab reveal ledger-walkthrough
```

`done` records the candidate's completion signal and runs the gate; it does not
reveal the next part. `reveal` requires that signal and a passing gate for the
**current saved code**. It may be used only when another part is available.
The CLI generates an unsolved candidate template. No candidate solution is
prepopulated by this demo.

There are three cumulative parts, starting with named-bay capacity reservations.
The later requirements, fixtures, hints, and complete references are private
interviewer material. Do not browse `pack.json`, this README's sibling source
files, or the standalone fixture tests as a candidate during an attempt.
The active-part view is the source of candidate requirements; never paste the
whole pack into the candidate workspace. These are logical practice boundaries,
not protection against a machine owner deliberately reading local files.

Try C++ with `--language cpp` instead. An existing compatible compiler is
required; this project does not install a toolchain. Python reference code uses
3.11+-compatible features; the verified runtime is reported by `doctor`.

```console
python -m interview_lab doctor
python -m interview_lab validate demos\ledger\pack.json --language python
python -m interview_lab validate demos\ledger\pack.json --language cpp --compiler g++
python -m interview_lab end ledger-walkthrough
python -m interview_lab reference ledger-walkthrough
```

Preparation privately validates the selected reference against **all explicit
public and hidden expectations before the clock starts**. A reference/fixture
disagreement is a pack defect, not a candidate failure. Reference access is
permitted only after the session ends, including timer expiry. Study mode can
provide explanations but does not unlock the reference early.

## Maintainer verification

```console
python -m unittest discover -s tests -p test_demo.py -v
```

These standard-library tests do not import the CLI or execution modules.
Every fixture carries a literal expected value or named exception; expectations
are not generated by running the reference. The tests additionally check
defensive copies, unchanged arguments, cancellation/replacement conservation,
atomic rollback, and order independence against an independent small-state
model. If a supported compiler is already on `PATH`, they compile and execute
all explicit fixtures against the C++ reference in a unique project-local
build directory, which is removed afterward. Otherwise that test is explicitly
skipped, not reported as C++ validation.

The complete solutions favor clarity: Python uses dictionaries; C++ uses
`std::map`. Routine lookup operations are expected constant time in Python and
logarithmic in C++; the batch extension copies availability and uses additional
sets. This is adequate for the stated task. The code is not a production
transaction engine, and allocation failures, concurrency, and persistent
storage are outside the stated contract.
